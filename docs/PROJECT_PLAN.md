# DartWatch — 기업 공시 모니터링 & 알림 서비스

## 1. 프로젝트 제목

**DartWatch (다트워치)**

기업 공시 모니터링 및 맞춤형 알림 서비스

- 영문명: DartWatch
- 프로젝트 유형: 개인 토이 프로젝트 / Backend 중심 웹 서비스
- 개발 목적: 백엔드 기술 역량 강화, 금융 데이터 활용, 포트폴리오 구축

## 2. 한 줄 설명

**OpenDART API를 활용하여 관심 기업의 신규 공시를 자동으로 수집하고, 사용자 설정 조건에 부합하는 공시를 이메일로 알려주는 맞춤형 모니터링 서비스.**

추후 카카오톡 및 Discord 등 다양한 알림 채널을 지원할 수 있도록 확장 가능한 구조로 설계한다.

## 3. 태그

`Stock` `OpenDART` `Spring Boot` `PostgreSQL` `REST API` `Scheduler` `Email` `Notification` `Docker` `Backend`

## 4. 해결하려는 문제

### 4.1 배경

주식 투자자는 기업의 주요 경영 활동과 재무 상태를 파악하기 위해 금융감독원 전자공시시스템(DART)을 확인한다.

하지만 여러 기업에 관심이 있는 경우 매번 DART에 접속해 새로운 공시를 검색해야 하는 불편함이 있다.

### 4.2 주요 문제점

1. **반복적인 공시 확인:** 새로운 공시가 등록되었는지 직접 확인해야 한다.
2. **관심 공시 선별의 어려움:** 수많은 공시 중 특정 기업이나 공시 유형만 확인하기 어렵다.
3. **중요 공시 확인 지연:** 공시가 등록되었다는 사실을 늦게 알 수 있다.
4. **분산된 정보 관리:** 여러 기업의 공시 이력을 한곳에서 추적하기 어렵다.
5. **정정공시 누락:** 이미 확인한 공시에 변경 사항이 발생해도 놓칠 수 있다.

### 4.3 해결 방향

사용자가 관심 기업과 공시 유형을 등록하면, DartWatch가 OpenDART API를 주기적으로 조회하여 신규 공시를 탐지한다.

탐지된 공시 중 사용자 조건에 일치하는 항목을 필터링하고, 이메일을 통해 해당 공시의 핵심 메타데이터와 원문 링크를 전달한다.

이를 통해 **공시 확인에 필요한 반복 작업을 자동화하고, 관심 기업의 주요 공시를 신속하게 확인할 수 있도록 지원한다.**

## 5. 주요 기능

### 5.1 관심 기업 관리

- 기업명 또는 종목코드를 이용한 기업 검색
- 관심 기업 등록 및 삭제
- 등록된 관심 기업 목록 조회
- 기업별 공시 모니터링 활성화 및 비활성화

### 5.2 기업 공시 자동 수집

- OpenDART API를 이용한 공시 목록 조회
- Spring Scheduler 기반 주기적 수집
- 신규 공시 및 정정공시 탐지
- 공시 접수번호를 이용한 중복 저장 방지
- 수집된 공시 메타데이터의 데이터베이스 저장

### 5.3 맞춤형 공시 필터링

- 관심 기업별 공시 필터링
- 공시 유형별 필터링
  - 정기공시
  - 주요사항보고
  - 발행공시
  - 지분공시
  - 기타공시
- 공시 보고서명 기반 키워드 필터링 (확장 기능)
- 알림 조건별 활성화 및 비활성화

### 5.4 알림 전송

**기본 알림 채널: 이메일 (MVP)**

- 신규 공시 감지 시 이메일 자동 전송
- 공시 기업명, 보고서명, 접수일 및 DART 원문 링크 포함
- 알림 전송 이력 및 성공·실패 상태 관리
- 전송 실패 시 재시도
- 동일 공시에 대한 중복 알림 방지

**추후 확장 알림 채널**

- 카카오톡: 카카오 '나에게 보내기' API를 통한 개인 알림
- Discord: Webhook을 이용한 지정 채널 알림
- 사용자별 알림 채널 선택 및 복수 채널 설정

### 5.5 공시 조회 및 관리

- 수집된 공시 목록 조회
- 기업명 및 공시 유형 검색
- 최신순 정렬 및 페이지네이션
- DART 공시 원문 바로가기
- 공시 수집 및 알림 처리 이력 확인

## 6. 사용자 시나리오

### 시나리오 1. 관심 기업 등록

1. 사용자가 DartWatch에서 기업을 검색한다.
2. 삼성전자, SK하이닉스, NAVER를 관심 기업으로 등록한다.
3. 관심 기업마다 알림을 받을 공시 유형을 설정한다.
4. 설정 정보가 데이터베이스에 저장된다.

### 시나리오 2. 신규 공시 감지 및 이메일 알림

1. DartWatch가 설정된 주기에 따라 OpenDART API를 호출한다.
2. 새로운 기업 공시를 발견한다.
3. 수집된 공시가 기존에 저장된 공시인지 확인한다.
4. 신규 공시라면 데이터베이스에 저장한다.
5. 등록된 관심 기업 및 공시 유형과 비교한다.
6. 조건에 일치하면 알림 전송 작업을 생성한다.
7. 이메일을 발송하고 전송 결과를 기록한다.

**이메일 알림 예시**

- 제목: `[DartWatch] 삼성전자 신규 공시 알림`
- 기업명: 삼성전자
- 공시명: 주요사항보고서(자기주식취득결정)
- 공시 유형: 주요사항보고
- 접수일: 2026-10-23 (예시)
- 원문: DART 공시 상세 페이지 링크

위 알림은 동작을 설명하기 위한 가상의 공시 사례다.

### 시나리오 3. 동일 공시 중복 수집

1. 스케줄러가 이전에 수집한 공시를 다시 조회한다.
2. 공시 접수번호(`rcept_no`)를 확인한다.
3. 이미 저장된 공시라면 중복 등록하지 않는다.
4. 기존에 정상 전송된 동일 조건의 알림도 다시 발송하지 않는다.

### 시나리오 4. 알림 채널 확장

1. 사용자가 이메일 외에 카카오톡 또는 Discord 알림을 설정한다.
2. 신규 공시가 탐지되면 서비스가 알림 대상과 채널을 결정한다.
3. 알림 채널별 구현체가 메시지를 발송한다.
4. 채널별 성공·실패 결과를 독립적으로 기록한다.

카카오톡 '나에게 보내기'는 개인 계정용으로 구현하며, 불특정 사용자에게 카카오톡을 일괄 발송하는 기능과는 구분한다.

## 7. 작동 방식

### 7.1 전체 처리 흐름

```text
[OpenDART API]
       │
       ▼
[공시 수집 스케줄러]
       │
       ▼
[신규 공시 판별]
       │
       ├── 기존 공시 → 처리 종료
       │
       ▼
[신규 공시 DB 저장]
       │
       ▼
[관심 기업 및 알림 조건 검사]
       │
       ├── 불일치 → 알림 생략
       │
       ▼
[알림 작업 생성]
       │
       ▼
[NotificationService]
       │
       ▼
[NotificationSender 인터페이스]
       │
       ├── EmailNotificationSender   (MVP)
       │
       ├── KakaoNotificationSender   (확장)
       │
       └── DiscordNotificationSender (확장)
       │
       ▼
[발송 결과 및 이력 기록]
```

### 7.2 공시 수집 방식

OpenDART의 공시검색 API를 주기적으로 호출하는 **Polling 방식**을 사용한다.

- 기본 조회 주기: 10분 (설정 가능)
- 조회 대상: 관심 기업이 포함된 국내 기업 공시
- 조회 범위: 최근 공시를 일부 중첩하여 조회
- 데이터 수집: 페이지네이션을 통해 결과 누락 방지
- 중복 판별: `rcept_no` 기준
- 오류 처리: API 장애 발생 시 재시도 및 다음 실행에서 누락 구간 재수집

API 응답의 최신성에 따라 실제 공시 등록부터 알림까지 지연이 발생할 수 있다.

### 7.3 알림 모듈 설계

알림 채널과 공시 처리 로직의 결합도를 낮추기 위해 Strategy 패턴을 적용한다.

공통 `NotificationSender` 인터페이스를 정의하고 이메일, 카카오톡, Discord 발송 구현체를 분리한다.

초기에는 `EmailNotificationSender`만 구현하지만, 추후 새로운 알림 채널을 추가하더라도 공시 수집 및 필터링 로직을 변경하지 않는 것을 목표로 한다.

### 8.2 MVP 완료 기준

**관심 기업 3개 이상을 등록하고, 신규 공시가 발견되었을 때 설정된 조건에 따라 이메일 알림을 중복 없이 수신할 수 있다.**

추가적으로 다음 조건을 만족해야 한다.

- 동일한 공시가 반복 조회되어도 중복 저장되지 않는다.
- 정상적으로 전송된 알림은 불필요하게 재전송하지 않는다.
- API 호출이나 이메일 발송에 실패해도 오류 기록을 남기고 재처리할 수 있다.
- 최초 수집한 과거 공시는 일괄 알림하지 않는다.

초기 MVP는 단일 사용자 환경으로 개발하여 사용자 인증과 복잡한 프론트엔드 구현을 생략한다.

## 9. 기술 스택 + 외부 API

### 9.1 기술 스택

| 영역 | 기술 | 역할 |
|---|---|---|
| Language | Java 21 | 백엔드 개발 |
| Framework | Spring Boot | REST API 및 비즈니스 로직 |
| Database | PostgreSQL | 공시·기업·알림 데이터 저장 |
| ORM | Spring Data JPA | 데이터 영속성 관리 |
| HTTP Client | Spring RestClient | OpenDART API 호출 |
| Scheduler | Spring `@Scheduled` | 정기 공시 수집 |
| Notification | Spring Mail | 이메일 알림 전송 |
| API Documentation | Springdoc OpenAPI | Swagger UI |
| Test | JUnit 5, Mockito | 단위 및 통합 테스트 |
| Infrastructure | Docker Compose | 로컬 개발 환경 |

초기 MVP에서는 Redis, Kafka, 별도의 Python 분석 서버, MSA 등을 도입하지 않는다.

필요성이 생기면 성능 및 운영 요구사항에 따라 단계적으로 추가한다.

### 9.2 외부 API

**① OpenDART API — 필수**

금융감독원에서 제공하는 전자공시 공개 API.

- 기업 고유번호 조회: `corpCode.xml`
- 공시 목록 조회: `list.json`
- 활용: 기업 정보 매핑, 신규 공시 수집, 공시 유형 필터링
- 비용: 무료 인증키 기반 (이용 한도 및 정책 준수)

공식 사이트: https://opendart.fss.or.kr/

**② SMTP — MVP 기본 알림**

Gmail 등의 SMTP 서버를 이용하여 이메일을 전송한다.

- 활용: 신규 공시 알림
- 구현: Spring Boot Mail
- 비용: 개인 계정의 무료 발송 범위 활용
- 인증: 계정 환경에 따라 앱 비밀번호 또는 OAuth 인증 적용

**③ Kakao Developers API — 추후 확장**

- 활용: 카카오톡 '나에게 보내기' 메시지
- 구현: Kakao OAuth 2.0 및 메시지 전송 REST API
- 요구사항: 토큰 발급·갱신, 동의항목 설정
- 대상: 본인 카카오 계정

공식 사이트: https://developers.kakao.com/

**④ Discord Webhook — 추후 확장**

- 활용: Discord 서버의 지정 채널로 공시 알림 전송
- 구현: HTTPS Webhook 요청
- 특징: 별도 봇 서버 없이 간단한 연동 가능

공식 문서: https://discord.com/developers/docs/resources/webhook

### 9.3 비용 및 운영 정책

- 로컬 PC와 Docker Compose 기반으로 개발하여 서버 비용 최소화
- 무료 API의 호출량 및 이용약관 준수
- SMTP 발송량 및 메시징 API의 속도 제한 준수
- API Key, OAuth 토큰, SMTP 비밀번호는 환경변수로 관리
- 공개 데모 운영 시 공시 데이터의 재배포 조건 확인

## 최종 개발 방향

DartWatch는 **신규 공시 수집 → 조건 필터링 → 이메일 알림**이라는 핵심 흐름을 우선 구현하는 소규모 백엔드 프로젝트다.

초기에는 Spring Boot와 PostgreSQL만으로 빠르게 MVP를 완성하고, 알림 기능은 공통 인터페이스로 분리하여 카카오톡·Discord 채널을 단계적으로 추가한다.

향후 StockLens에서는 DartWatch의 공시 수집 및 이벤트 탐지 기능을 재사용하고, 주가 데이터와 통계 분석 기능을 추가하여 금융 데이터 분석 서비스로 확장할 계획이다.
